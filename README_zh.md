# Mlog Dev Tools

一个原先名为 Mlog Assertions 的模组。

> [!NOTE]
> 在拥有大量处理器的地图上使用此模组可能会对游戏性能产生负面影响。

此模组旨在让 Mindustry Logic 中的调试变得更容易一些。提供的功能：

* 增强的 **Vars** 界面：以完整精度显示数值和颜色值，按名称排序变量，将变量和文本缓冲区内容复制到剪贴板。
* **Memory** 界面，用于检查内存块的内容，使用与 **Vars** 界面相同的界面。包含清除（重置）内存块内容的命令。
* 用于覆盖指令限制的设置（限制最多可增加到 2000 条指令）。这允许你在代码中插入调试代码（例如额外的 `print` 指令），即使已超过原始指令限制。
* **快照** 允许保存、查看和恢复逻辑处理器、内存块以及地图上所有其他块的状态。快照可以手动创建，也可以使用逻辑指令创建。每个块保留有限数量的快照，允许查看创建快照时块的精确状态。
* 用于执行运行时检查、记录消息和报告错误的自定义 mlog 指令。
* 指示已停止的处理器、正在执行 `wait` 的处理器以及失败的运行时检查。

# Vars 界面 （变量显示）

**Vars** 界面已得到增强：
* 包含额外的处理器变量（文本缓冲区内容、当前等待时间、`@unit`、`@ipt`）。
* 数值以可配置精度显示。整数值与十进制值清晰区分。
* 颜色范围内的数值格式化为颜色字面量（例如 `%e55454ff`），颜色本身用字形表示。
* 可选择以十六进制或十进制格式显示数字（包括内存单元地址）。
* 可选择按名称排序变量或恢复其原始顺序。
* 可选择隐藏临时变量和处理器链接。
* 将变量列表或文本缓冲区内容复制到剪贴板的命令（在此模组的先前版本中，这些按钮直接包含在处理器界面上）。

# 显示内存块内容

点击内存块时，现在会显示配置按钮。该按钮打开一个 **Memory** 界面，类似于上述 **Vars** 界面。所有与内存块特性相关的选项都可用。此外，**Edit** 按钮允许你清除内存块内容、将其复制到剪贴板并重新导入。

剪贴板中保存的表格可以被修改（例如在电子表格中），然后重新导入内存块。表格的列由制表符分隔，单元格地址始终以十进制给出。字符串写成用引号括起来的字面量，其中会丢失或破坏表格的字符使用转义序列编码（`\n`、`\"`、`\\`、`\uXXXX`）。数字可以按十进制、颜色、十六进制或二进制形式输入，非有限值会以 `null` 写入和导入，因为它们无法在内存块中表示。无法解析的行会被报告并跳过，只有在整个表格解析完成后才会更改内存块。没有文本形式表示的值（对单位、建筑和内容（contents）的引用）也会导出，但无法恢复。

# 快照

快照捕获处理器（其所有变量）、内存块（所有单元）或一般块（所有可感测属性）的状态。该模组允许创建和查看快照。

## 快照类型

有三种类型的快照：_隔离_、_连接_ 和 _全局_。隔离快照仅保留单个块的状态。连接快照保留一个块的状态，以及中央块变量中找到引用的所有块的状态。全局快照保存地图上所有 _逻辑_ 块的状态（即仅处理器和内存单元，而非一般所有块）。

快照始终分配给特定块，并保存在该块的列表中。当快照数量达到（可配置的）限制时，较旧的快照会从每个块中移除。

连接和全局快照可从其中包含的任何块访问。当快照从其所包含的所有块中过期移除时，它就不复存在。

> [!NOTE]
> 快照不会随地图保存；当地图关闭时，所有快照都会丢失。

## 快照创建和使用

连接快照可以从用户界面创建，使用 Vars/Memory/Properties 界面，或者（对于处理器和内存单元）使用块配置菜单。

`snapshot` 指令可以使用任何块作为中央块来创建任何类型的快照。创建快照没有速率限制，但显然滥用该功能可能会导致性能问题。

可以使用 Vars/Memory/Properties 界面查看快照。处理器或内存状态可以从快照恢复。

可以从用户界面删除快照。

## 用户界面

内存块获得用于创建和查看快照的配置菜单。处理器的配置菜单通过用于创建和查看快照的按钮得到增强。任何块的 Properties 界面都可以通过三连击该块打开（延迟可在设置中配置，将延迟设为 0 会禁用该功能）。

Vars/Memory/Properties 界面上提供简要帮助界面。

## 设置

可以通过将保留快照的最大数量设为 0，在设置中完全停用快照。禁用后，无法以任何方式创建快照，并且用户界面中不会出现任何与快照相关的元素。

可以激活在命中断点或断言失败时创建快照。

# 自定义指令

这些自定义指令由 [Mindcode](https://github.com/cardillan/mindcode) 使用，以提供调试支持或执行运行时检查。它们也可以被其他编译器或手写 mlog 使用。

当断言失败时，程序执行会在给定指令处停止，并在处理器上方显示附带消息。

## 指令 `assert`

此指令断言给定条件为真。该指令接受以下参数：

* `value`、`operator`、`comparison`：指定要检查的条件。
* `message`：断言失败时要显示的错误消息。在用户界面中，该字段仅在点击按钮后显示。消息可以包含形如 `{1}`、`{2}` 或 `{3}` 的占位符，分别对应 `value`、`comparison` 和 `operator`。此外，用花括号（`{` 和 `}`）括起来的变量名会被替换为实际变量值。如果消息不是字符串或为空字符串，则显示默认消息。

## 指令 `assertbounds`

这是一条复杂指令，最适用于验证用作数组索引的变量值是否在边界内。对内部数组使用越界索引可能会导致不稳定、难以诊断的行为。该指令接受以下参数：

* `type`：关键字。指定被测试值所需的类型：
  * `any`：允许任何值，
  * `notNull`：允许除 `null` 以外的任何值，
  * `decimal`：要求数值，
  * `integer`：要求整数值，
  * `multiple`：要求是指定倍数的整数值。
* `multiple`：当 `type` 为 `multiple` 时所需的倍数。
* `min`：允许的最小值。对应 `{1}` 消息占位符。
* `opMin`：`lessThan` 或 `lessThanEq` 之一，指定允许范围是否包含最小值。对应 `{4}` 消息占位符。
* `value`：被测试的值。对应 `{2}` 消息占位符。
* `opMax`：`lessThan` 或 `lessThanEq` 之一，指定允许范围是否包含最大值。对应 `{5}` 消息占位符。
* `max`：允许的最大值。对应 `{3}` 消息占位符。
* `message`：断言失败时要显示的错误消息。在用户界面中，该字段仅在点击按钮后显示。消息可以包含形如 `{1}` 到 `{5}` 的占位符，对应上述值和指令参数。此外，用花括号（`{` 和 `}`）括起来的变量名会被替换为实际变量值。如果消息不是字符串或为空字符串，则显示默认消息。

## 指令 `assertequals`

此指令将实际值与期望值进行比较，如果它们不相等，则显示给定消息。该指令接受以下参数：

* `expected`：期望值。
* `actual`：实际值。
* `message`：断言失败时要显示的错误消息。在用户界面中，该字段仅在点击按钮后显示。消息可以包含形如 `{1}` 和 `{2}` 的占位符，分别对应期望值和实际值。此外，用花括号（`{` 和 `}`）括起来的变量名会被替换为实际变量值。如果消息不是字符串或为空字符串，则显示默认消息。

这些值使用 `strictEqual` mlog 运算符进行比较。

## 指令 `asserttype`

此指令将运行时数据类型与期望值进行比较，当值的类型不是期望类型时显示给定消息。该指令接受以下参数：

* `expectedType`：期望的数据类型。支持的数据类型有：
  * `number`
  * `string`
  * `content`
  * `item`
  * `block`
  * `bulletType`
  * `liquid`
  * `statusEffect`
  * `unitType`
  * `weather`
  * `team`
  * `unitCommand`
  * `unitStance`
  * `unit`
  * `building`
  * `processor`
  * `memory`
  * `message`
  * `display`
  * `canvas`
  * `property`
  * `readable`
  * `writable`
  * `senseable`
* `actualValue`：被测试的值。
* `message`：断言失败时要显示的错误消息。在用户界面中，该字段仅在点击按钮后显示。消息可以包含形如 `{1}` 和 `{2}` 的占位符，分别对应期望值和实际值。此外，用花括号（`{` 和 `}`）括起来的变量名会被替换为实际变量值。如果消息不是字符串或为空字符串，则显示默认消息。

> [!NOTE]
> 此指令仍在开发中，对于某些参数组合可能无法按预期工作。

## 指令 `assertflush`

此指令必须在向文本缓冲区生成文本的代码段开头使用（使用任何打印指令，`print`、`printchar` 或 `format`）。然后使用 `assertprints` 指令将程序生成的输出与期望字符串进行比较。该指令接受以下参数：

* `position`：输出变量，接收文本缓冲区中的当前位置。

## 指令 `assertprints`

此指令将程序生成的输出与期望字符串进行比较。该指令接受以下参数：

* `position`：被测代码开始时文本缓冲区中的位置（必须是 `assertflush` 指令使用的变量）。
* `expected`：期望字符串。
* `message`：断言失败时要显示的错误消息。在用户界面中，该字段仅在点击按钮后显示。消息可以包含形如 `{1}` 和 `{2}` 的占位符，分别对应期望值和实际值。此外，用花括号（`{` 和 `}`）括起来的变量名会被替换为实际变量值。如果消息不是字符串或为空字符串，则显示默认消息。

当指令完成时，文本缓冲区会恢复到上一个 `assertflush` 指令的状态。

> [!NOTE]
> 文本缓冲区的内容不会保存到地图文件中。因此，从存档文件加载游戏后，`asssertprint` 指令可能会虚假失败。

## 指令 `breakpoint`

此指令带有一个条件（就像 `jump` 指令一样）。当条件满足时，游戏会在断点发生时的精确状态暂停，并且带有断点的处理器会在屏幕上居中。命中断点后，当前处理器或任何其他处理器中的其他指令都不会执行，所有处理器中的所有逻辑变量以及所有内存单元的内容都应保持不变。但是，在命中断点之后、游戏正确暂停之前，单位 and 建筑可能会改变自身状态或其他单位/建筑的状态。

多人游戏中会忽略断点。

> [!NOTE]
> 取消暂停游戏后，执行会照常继续，但由于处理器受到操作，指令执行顺序可能会改变。依赖两个或多个处理器同步执行（例如子帧）的蓝图可能会受到影响。

## 指令 `error`

此指令显示错误消息并停止程序执行。该指令接受以下参数：

* `message`：要显示的错误消息。
* `p1` .. `p9`：要在错误消息中显示的附加参数。

消息中用花括号（`{` 和 `}`）括起来的变量名会被替换为实际变量值。如果消息包含形如 `{1}` 到 `{9}` 的占位符，它们会被相应参数替换。如果有其他未被消息使用的参数，且其值不是字面量 `null`，它们会逐个追加到消息中。在这种情况下，字符串值会用引号括起来。颜色范围内的数值会格式化为颜色字面量（例如 `%e55454ff`）。

## 指令 `log`

此指令将消息写入游戏日志文件。用户需自行避免向文件中写入过多错误消息。该指令接受以下参数：

* `level`：消息的日志级别，为 `debug`、`info`、`warning` 或 `err` 之一。
* `message`：要显示的错误消息。
* `p1` .. `p9`：要在错误消息中显示的附加参数。

消息中用花括号（`{` 和 `}`）括起来的变量名会被替换为实际变量值。如果消息包含形如 `{1}` 到 `{9}` 的占位符，它们会被相应参数替换。如果有其他未被消息使用的参数，且其值不是字面量 `null`，它们会逐个追加到消息中。在这种情况下，字符串值会用引号括起来。颜色范围内的数值会格式化为颜色字面量（例如 `%e55454ff`）。

## 指令 `snapshot`

创建给定块的快照。该指令接受以下参数：

* `type`：要创建的快照类型：
  * `isolated`：仅捕获目标块的状态。
  * `connected`：捕获目标块的状态，以及目标块变量中找到引用的所有块的状态——如果目标块是处理器或内存块。
  * `global`：捕获地图上所有处理器和内存块的状态（不包括常规块）。
* `target`：目标块（`global` 快照不使用）。
* `name`：快照的名称。

创建快照没有速率限制，但显然滥用该功能可能会导致性能问题。

# 设置

## 禁用断点

禁用处理器中的断点：执行会在下一条指令继续，而不会暂停。

## 断言失败时断点

启用时，失败的断言会像断点一样处理，然后执行在下一条指令继续。如果断点被禁用，断言会被完全忽略。

## 命中断点时分离相机

当命中断点时，相机会分离，以便处理器保持在视野中。取消暂停游戏时，相机会恢复原始状态。如果分离相机导致一些问题，可以将其禁用。

## 指令限制

允许增加逻辑处理器中的指令限制。增加的限度可用于向程序添加调试代码，否则由于超出标准指令限制，这些代码将无法容纳。

## 显示长于（秒）的等待

设置 `wait` 指令参数中指定的最小等待时间，超过该时间会在处理器上指示等待。可以通过将值设为 `0` 来完全隐藏指示。

## 每 tick 处理器更新数

为了指示已停止和正在等待的处理器，模组需要定期检查地图上所有处理器的状态。每个 tick 最多检查给定数量的处理器。如果地图上有大量处理器并且性能受到影响，降低此值可能会有所帮助。

## 视觉警告

控制是否在地图本身上使用视觉效果来吸引对已停止或失败处理器的注意。效果可以完全关闭、仅在处理器停止或失败时执行一次，或以给定间隔周期性执行。

## 三连击速度

在配置的时间间隔内三连击一个块会打开该块的 Sensors/Vars/Memory 界面。

## 快照限制

**每个块**保留的最大快照数量。将此值设为 0 会完全停用快照，并从用户界面中移除与快照相关的功能。

> [!NOTE]
> 较大的值可能会导致内存或性能问题。

## 命中断点时创建快照

启用时，当触发断点时会自动创建连接快照。

## 断言失败时创建快照

启用时，当断言失败时会自动创建隔离快照。

## 变量更新

Vars/Memory/Properties 界面上变量更新之间的游戏 tick 数。

## 有效数字

在 Vars/Memory/Properties 界面中显示十进制数字时使用的有效数字位数。

## 对齐

Vars/Memory/Sensors 界面上显示值的默认对齐方式。
